Student Request Form - Document Submission

What to Show: The document request form with student information and document type selection.

The Student Request Portal allows students to submit new document requests through a well-organized form. The form displays pre-filled fields for Student ID and Full Name that are automatically populated from the system database, reducing manual entry errors and ensuring data accuracy.

Figure 6
Document Requests Queue - Active Requests Management
Screenshot: Request Management Table with Status Updates
What to Show: The request management table showing all active requests with status update dropdown and action buttons.

The Active Requests page displays all incoming student document requests in a comprehensive, organized table format. Each row represents a request with columns for Ticket & Student information, Document Type, Current Status, Request Date, and available Actions. Records Officers can view all essential request details in a single view for efficient processing.

The interface provides dynamic status management through a dropdown menu allowing Records Officers to update request status through the workflow stages (Pending, Processing, Processed, Ready to Release, Released, Rejected). A remarks field enables adding processing notes for internal documentation. Direct "Open Form Maker" links provide quick access to generate documents for selected requests. This queue management system enables Records Officers to efficiently process requests while maintaining workflow transparency.

Figure 7
Form 137 Generator - Document Creation Interface
Screenshot: Form 137 Generator with Student Search
What to Show: The Form 137 Maker page with student search field and load button.

The Form 137 Generator enables Records Officers to create official student permanent records efficiently. The interface includes a search field for locating student records by student number and a Load button to retrieve the selected student's information from the database. The page clearly identifies its purpose as "Official Student Permanent Record Maker".

Once a student record is loaded, Records Officers can review all student information, make any necessary edits or corrections, and generate the official PDF document for printing or digital distribution. The system automatically pulls data from the student database to pre-populate forms, reducing manual entry errors. This streamlined document generation process significantly reduces the time needed to create official records.

Figure 8
Form 138 Maker - Report Card Generation
Screenshot: Form 138 Report Card Generation
What to Show: The Form 138 generation page with student name, school year, and subject ratings table.

The Form 138 Maker facilitates the generation of official student report cards for specific school years. The interface displays student name and school year fields for identifying the subject of the report, along with fields for specifying the grade level. A comprehensive subject ratings table lists academic subjects with columns for each quarter grade (Q1, Q2, Q3, Q4) and final grade.

Records Officers can add multiple subjects to the report card using an "Add Subject" button, and remove incorrect entries with action buttons. The organized table layout ensures accurate grade entry while maintaining professional document formatting. The "Generate" button creates the official report card in PDF format for distribution to students or archival.

Figure 9
Grade Portal Upload - Form 138 Management
Screenshot: Grade Portal with Upload and Search Interface
What to Show: The Grade Portal with upload form and Grade Viewer search interface.

The Grade Portal provides a dual-interface page for comprehensive grade management. The left section provides an "Upload Form 138" interface where Registrars enter student information (Student Number, Student Name), academic details (School Year), and upload reference files containing grade data (Excel, PDF, or Image formats). The right section contains a "Grade Viewer" interface that allows Records Officers to search for and retrieve existing student grade records by student number. The two-column layout provides an intuitive workflow for comprehensive grade management and record retrieval.

Request History - Archive Management
Screenshot: Request Archive with History Table
What to Show: The request history page showing completed/rejected requests table structure and empty state.

The Request History page (Records Archive) maintains a comprehensive archive of all completed and rejected document requests. The interface displays a table structure with columns for Ticket & Student information, Document Type, Final Status, Date Processed, and Processing Remarks. This organized format enables Records Officers to quickly locate and review past request details.

The page provides an important audit trail of all processed requests, essential for record-keeping and compliance verification. Administrators can filter and search historical records by date range, student, or document type. This archive functionality supports institutional recordkeeping requirements and enables tracking of request processing trends over time.

System Audit Logs - Activity Tracking
Screenshot: System Activity Log with Event History
What to Show: The System Audit Logs page with activity history table showing timestamp, user, action, module, and status.

The System Audit Logs page monitors and displays all system activities and user actions in real-time. The activity history table includes comprehensive columns for Timestamp (recording when actions occurred), User (identifying who performed the action), Action type (describing what was done: Updated Request Status, Submitted Request, Full System Reset, etc.), Module affected (Requests, Grades, User Management), and operation Status (Success/Failure indicators).

System Summary

The RequestHub system provides a comprehensive solution for managing student document requests with distinct user interfaces optimized for each user role:

User Roles & Features:

  • Students: Document request submission, real-time status tracking, and request history viewing
  • Records Officers: Request queue management, document generation, and workflow processing
  • Registrars: Grade management, document submission, and academic record storage
  • Administrators: Complete system control, user management, analytics, and system configuration

Key Functions:

  • Student document request management with multiple document types support
  • Role-based access control with secure authentication
  • Automated document generation (Forms 137, 138, Good Moral, Diploma)
  • Grade portal for academic record management and storage
  • Request workflow management with status tracking and notifications
  • Comprehensive analytics and reporting for decision-making
  • System audit logging for accountability and compliance
  • User management and role-based permission assignment
  • System configuration and maintenance controls
