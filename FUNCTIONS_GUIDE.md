# Functions of the Proposed System - Screenshots Guide

## a. Login and Authentication

**Figure 1. Records Management System Login Page**

The login page presents the authentication interface for the Fiat Lux Academe Document Request Hub, the proposed records management system. Users can log in using their username/student ID and password. The system provides role-based login options (Admin, Student, Registrar, Records Officer) displayed at the bottom, allowing quick access for each user type. The login interface ensures only authorized personnel can access sensitive student records while maintaining system security. The page features the institution branding (Fiat Lux Academe logo) and presents a clean, professional authentication form with clear field labels and an intuitive layout.

---

## b. Student Dashboard and Document Request Interface

**Figure 2. Student Dashboard and Request Management**

The student dashboard displays an intuitive interface for document requests. Students can view available document types (Form 137, Form 138, Good Moral Certificate, and Diploma) and access their request history. The dashboard shows all submitted requests with their current status (pending, processing, approved, rejected), submission date, and expected completion date. Students can submit new requests by selecting the desired document type and clicking the request button.

---

## c. Student Request Form and Submission

**Figure 3. Student Document Request Form**

The request submission form allows students to apply for official documents. The form displays required fields for request information and student details. Upon completion, students can preview their request details before submission. The form includes clear instructions and validation to ensure all necessary information is provided before submission.

---

## d. Records Officer Dashboard - Request Queue

**Figure 4. Records Officer Request Management Queue**

The Records Officer dashboard displays all incoming student requests in a centralized queue. The interface shows a table listing requests with student information, requested document type, submission date, and current status. Records Officers can view pending requests, update request status, add processing notes, and mark requests as completed. Search and filter options allow quick access to specific requests.

---

## e. Request Status Update Interface

**Figure 5. Request Status Update and Processing**

The status update interface enables Records Officers to manage document requests through the workflow. Records Officers can update request status from pending to processing or approved, add internal notes about the request progress, and assign priority levels. The interface displays all request details and history of previous status changes for complete transparency.

---

## f. Document Generation - Form 137

**Figure 6. Form 137 Generation Interface**

The Form 137 generation interface displays student academic records ready for document creation. The system shows student information pre-populated from the database including name, student number, and academic details. Records Officers can review the information, make necessary edits, and generate the official Form 137 document. A preview option allows verification before final generation.

---

## g. Document Generation - Form 138

**Figure 7. Form 138 Generation and Preview**

The Form 138 generation tool allows Records Officers to create medical/dental forms. The interface displays student information and form-specific fields. Records Officers can preview the complete document before generating the final PDF. The generated documents maintain official formatting and can be downloaded or printed directly from the system.

---

## h. Grade Portal Upload Interface

**Figure 8. Grade Upload and Management Portal**

The Grade Portal provides Registrars with an interface to upload student grade data. The page displays an upload form where Registrars can select grade files and submit them for processing. Below the upload section, a table shows previously uploaded grades with details of students, courses, and grades. The system validates data and displays any errors requiring correction.

---

## i. Grade Records Table and Management

**Figure 9. Grade Records Viewing and Editing**

The grade records interface displays all uploaded student grades in an organized table format. Registrars can view complete grade information by student and course. The interface provides options to edit grades, delete incorrect entries, and filter records by student or course. Summary statistics show total students processed and grade distribution.

---

## j. Analytics Dashboard - System Metrics

**Figure 10. Analytics Dashboard and Reporting**

The analytics dashboard provides comprehensive insights into system usage and document processing metrics. The interface displays visual charts showing request volume trends, document type distribution, and request status breakdown. Summary cards show key metrics including total requests processed, average processing time, and pending requests. Users can toggle between graph view and data card view.

---

## k. Request History and Reports

**Figure 11. Request History and Processing Reports**

The request history interface displays all processed requests with complete details. Users can filter by date range, document type, or status. The page shows submission date, approval date, student information, and processing duration. Export options allow saving reports in CSV or PDF format for documentation and presentation purposes.

---

## l. Activity Logs and Audit Trail

**Figure 12. System Activity Logs**

The activity logs page displays a chronological list of all system activities and user actions. Each entry shows the timestamp, user who performed the action, action type (created, updated, deleted, approved), and affected record details. The interface includes search functionality to filter logs by date range, user, or action type. Administrators use these logs for auditing, compliance verification, and investigating system usage.

---

## m. User Management Interface

**Figure 13. User Account Management**

The user management interface allows administrators to manage system users and assign roles. The page displays a table of all users showing name, role, email, and account status. Administrators can create new users by entering personal details and selecting a role. The system auto-generates secure passwords, and administrators have the option to manually set passwords. The interface also provides options to edit user information, deactivate accounts, or delete users.

---

## n. Role Assignment and Permissions

**Figure 14. Role-Based Access Control Management**

The role management interface enables administrators to define user permissions and access levels. The interface shows different user roles (Student, Records Officer, Registrar, Administrator) with their assigned permissions. Each role displays accessible features and functions. Administrators can modify role permissions to control system access and ensure proper workflow hierarchy.

---

## o. Settings and System Configuration

**Figure 15. System Settings and Configuration**

The settings page provides administrators with configuration options for the records management system. The interface displays various settings categories including system preferences, notification settings, and document templates. Administrators can modify settings such as default loan durations, fine amounts, and system notifications. Changes are saved and applied system-wide.

---

## p. Main Dashboard Overview

**Figure 16. System Dashboard - Overview and Navigation**

The main dashboard serves as the central hub after user login, displaying role-specific information and quick-access buttons. The interface includes navigation menu, pending tasks widget, recent activities, and system notifications. The dashboard layout is responsive and adapts to different user roles, showing only relevant information and functions for each user type.

---

## Summary

The Records Management System provides a comprehensive solution for managing student document requests and academic records. Key functions include student document request management, automated document generation, grade management, request workflow processing, comprehensive analytics, activity logging, role-based access control, and secure user management. The system improves efficiency, reduces manual processing time, and provides transparency throughout the document request workflow.
